Do not iframe the GitHub Pages application, import code from the live site at runtime, or copy the Topology Validator controller wholesale.1. Purpose and acceptance boundary
This procedure converts the current LFEA workbench into an SVG-first engineering modelling and review surface while preserving all existing LFEA numerical authorities. The SVG layer shall author and review piping source geometry, component identity, supports, loads, code points and results. It shall not construct stiffness, derive code stress, repair topology or become the source of solver truth.
• SVG is the primary engineering authoring surface for projected XY, XZ, YZ and ISO views.
• The authoritative source is a versioned LFEA engineering model, not DOM elements or SVG path data.
• Pointer movement creates transient preview only; accepted commands update the draft/model through a revision-checked gateway.
• Solver, recovery and B31.3 packages consume immutable LFEA contracts and never inspect the SVG DOM.
• Three.js/WebGL may remain available as a read-only 3D inspection backend, but it is not required to author source geometry.

• Do not preserve Topology Validator's support-only domain restriction. Create an LFEA domain adapter for PIPE, BEND, TEE, REDUCER, RIGID, SUPPORT, LOAD and CODE_POINT entities.
• Do not preserve a read-only adapter descriptor. LFEA authoring requires accessMode = EDITABLE and a valid EngineeringSvgCommandGateway.v1.
• Do not use localeCompare() for canonical provider or entity ordering. Use the Advanced_Analysis ASCII comparator so locale cannot alter engineering identity.
• Do not use manual viewBox/bounding-rectangle pointer mapping without testing preserveAspectRatio gutters. Prefer SVG getScreenCTM().inverse() for screen-to-SVG conversion, with a tested fallback.
• Do not reuse Topology-specific CSS selectors, event names, evidence schemas or source IDs as LFEA authority.

• Every SVG primitive carries data-scene-entity-id and data-source-entity-id.
• DOM IDs are render-session details and never enter engineering hashes.
• One physical source component may create multiple render primitives, but every primitive maps back to exactly one source/component identity and role.
• Result overlays cite recoveryHash and codeAssessmentHash but cannot mutate either package.
6. Projection and viewport procedure
1. Implement one world-coordinate projection service supporting XY, XZ, YZ and deterministic ISO.
2. Create one fit transform from visible engineering bounds; retain it in viewport state.
3. Render all semantic layers through the same world-to-screen matrix.
4. Use SVG viewBox for zoom/pan; never scale engineering coordinates inside the source model.
5. Convert pointer coordinates with getScreenCTM().inverse(); reject a null or singular CTM.
6. Retain the manual viewBox mapping only as a tested fallback for constrained browser environments.
7. Projection or display changes do not invalidate engineering packages.
export function clientToSvgPoint(svg, clientX, clientY) {
  const matrix = svg.getScreenCTM();
  if (!matrix) {
    throw new Error('LFEA_SVG_SCREEN_MATRIX_UNAVAILABLE');
  }

  const determinant =
    matrix.a * matrix.d - matrix.b * matrix.c;

  if (!Number.isFinite(determinant) || determinant === 0) {
    throw new Error('LFEA_SVG_SCREEN_MATRIX_SINGULAR');
  }

  return new DOMPoint(clientX, clientY)
    .matrixTransform(matrix.inverse());
}6.1 3D editing discipline in projected SVG
• A free pointer drag may change only coordinates visible in the active projection.
• Movement along the hidden axis requires an explicit axis handle, typed coordinate or synchronized second view.
• ISO drag is axis-constrained; free-plane ISO movement is prohibited for engineering commits.
• Topology-changing operations show a preview and require explicit acceptance.
• Any edit that cannot be represented uniquely in the active projection is BLOCKED with a recommendation to switch projection or enter dimensions.
7. Command and draft lifecycle
pointerdown
  -> capture pointer
  -> record base source revision
  -> create transient preview state

pointermove
  -> pure projected constraint solve
  -> update preview SVG only
  -> no model mutation
  -> no hash change

pointerup
  -> construct LfeaSvgCommand.v1
  -> validate current base revision
  -> validate component-specific semantics
  -> execute through EngineeringSvgCommandGateway.v1
  -> append one history command
  -> rebuild accepted scene
  -> invalidate downstream solver/result packages

Escape / pointercancel
  -> discard preview
  -> restore accepted scene

EntityPermitted and prohibited behaviorPIPEMove endpoint, split span, change endpoint coordinate, assign section/material. A zero-length result blocks. Intermediate support/load/code stations are preserved or explicitly remapped.BENDEdit tangent points, centre/radius/sweep or declared arc authority. Free polyline deformation is prohibited. Commit must re-pass bend geometry and B-3.2 subdivision/flexibility checks.TEEMove the explicit junction or leg endpoints. The UI may preview leg roles, but direction-vector topology remains the run/branch classifier.REDUCEREdit length, end stations and section mapping. Visual taper is derived; the stepped approximation and CONDITIONAL state remain visible.RIGID finite bodyEdit endpoints, length and CG through exact fields/handles. Zero length blocks unless the governed weight-lump rule applies.RIGID linkEdit master, slave and offset; code-stress eligibility remains false and cannot be changed in the SVG UI.SUPPORTMove support location/offset, edit direction/stiffness through properties. One-way/gap/friction semantics remain outside the linear release.LOADMove an application station only through an accepted source edit; visual arrow scaling is display-only.9. Snapping and constraints
Snap modeAuthorityENDPOINTCanonical node or component port.MIDPOINTPipe span midpoint; creates a preview station, not an implicit node until accepted.CENTREBend centre or circular component centre.INTERSECTIONProjected intersection; 3D compatibility must be proven before commit.TANGENTBend tangent geometry under the active projection.PERPENDICULARConstraint to a selected reference span.AXISGlobal X, Y or Z axis-constrained movement.GRIDDisplay convenience only; accepted coordinate is the exact source value.9.1 Snap selection rules
• Snap aperture is a display profile expressed in screen pixels and does not enter the engineering hash.
• Candidate IDs are deterministic and ASCII sorted.
• Equal-distance ties use declared provider priority followed by candidate ID.
• A projected intersection that represents skew 3D lines is visible as NON_COMMITTABLE.
• The committed engineering point is recalculated and validated in world coordinates.
10. Result overlays
• Deformation is display-only and requires an explicit positive scale.
• Force and moment diagrams consume B-3.4 recovery values and retain local/global basis labels.
• B31.3 utilization consumes B-4.0 code results and retains category, code point, combination and source dataset identity.
• The workspace must not recompute stress, SIF, allowable or utilization.
• A stale result package is not rendered as current and is not exportable.

• Reject imports from solver, result-recovery or B31.3 packages inside SVG renderer/controller modules.
• Reject stress, SIF, allowable or utilization arithmetic in workspace code.
• Reject direct source mutation from pointermove.
• Reject DOM IDs or SVG path data in engineering hashes.
• Reject localeCompare() in canonical ordering.
• Reject Math.random(), Date.now() and random UUIDs in engineering commands or scene identity.
• Reject runtime network imports from XML_Compare_Utilities or GitHub Pages.
• Reject Topology-specific source schemas in LFEA production contracts.
• Reject component flattening from BEND/TEE/REDUCER/RIGID to PIPE.
• Reject an editable adapter without a revision-checked command gateway.
